### Changed — design is conditional on the run's assurance, and review enforces the level rather than a bare event (#352)

`harness start` now resolves an issue's `assurance:<level>` label once and
snapshots the result on the run row (`assurance`, `assurance_reason`, both
additive nullable columns). `harness/assurance.py` is the single home for the
vocabulary (`trivial | simple | complex`), the resolution, the ledger coercion,
and the required-stages table that `design` and `review` both read.

`harness design` invokes no engine, reads no ticket, writes no ledger event and
posts no comment where the run's level does not require a design; it exits 0
with the same six-key `DesignOutput` carrying `status: "not_required"`.

`harness review` refuses a run that owes a design before any engine runs —
`no_design` when none was recorded, and the new `design_not_usable` when the
recorded attempt did not succeed. ADR 0007 D4's "a failed attempt satisfies the
check" is narrowed to the levels that do not require the stage, not removed.

Everything unresolved fails safe to `simple`, the level that still requires an
LLM review: no label, conflicting labels, an uninterpretable value, and every
run row written before the migration. `trivial` is recognized and upgraded to
`simple` — the trivial fast path has **not** shipped, and no run can bypass
review until the deterministic certification path does.

An existing checkout's ledger is handled at both ends, because `_migrate` runs
only from `init_db` and `init_db`'s one caller is `start`: `start` migrates
before its first read of the new columns, and `read_run_assurance` reads an
absent column as no recorded assurance rather than raising past the verb's JSON
refusal contract.
