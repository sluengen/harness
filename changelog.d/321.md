### Removed — per-ticket model tiering retired; the review model is one configured value (#321)

ADR 0005's `build:<tier>` / `review:<tier>` GitHub labels are gone, along with
`resolve_model_tier`, `ModelTier`, and the tracker `fetch_issue` round-trip the
review path made on every run to read them. The claude review engine's model is
now `CONTEXT.md`'s `loop.review_model` (default `sonnet`) — one value, one edit
to change — read off the `LoopBudget` the verb already loads, so resolving it
costs no I/O at all. `harness review --model <alias>` is unchanged.

Measured 2026-08-04, neither half of the mechanism was doing work: `build:` is
consumed by nothing and was set on 0 of 25 open issues, and `review:` was a real
control signal that was never once set, so every recorded review resolved past it
to the same fallback. The value ships as `sonnet` deliberately — retiring the
mechanism and moving the model in one change would confound the two.

The knob is a plain string, not a two-value enum: a third alias is a one-line
`CONTEXT.md` edit rather than a code change, and an unrecognized alias fails
loudly at the claude CLI instead of being silently coerced to the default.
