### Changed — decision storage is repo-configurable, embedded-first (#330)

Universal `spec-authoring` stated a flat prohibition — "There is no separate `decisions/` folder and no standalone ADRs" — while this repo declares `paths.decisions` and keeps a growing numbered ADR set there. An agent applying the universal rule here was instructed to dismantle the repo's own canonical decision record, and a future decision could legitimately land in either of two homes.

Embedded stays the default and the optional `CONTEXT.md` `paths.decisions` key is now the **only** switch — no strategy enum, nothing that can disagree with the path. Declare it and that directory holds decisions that are cross-cutting, consequential, and expensive to reverse; a decision that merely touches several files does not clear the bar, and one that governs a single feature never does. Each qualifying decision has one canonical record, which affected feature specs **link** to rather than restate. Placement, numbering, and supersession inside the directory are deferred to the repo's architecture index, so universal prose names the key and never a concrete path.

Eight installed surfaces move with it: `spec-authoring` (the rule's home) `0.9.3` → `0.10.0`, `architecture` `0.7.0` → `0.7.1` (its pointer conditionalised), `architect` `0.2.0` → `0.3.0` (files an ADR where one is configured; still refuses to invent a directory the repo has not), `steward` `0.2.1` → `0.2.2` (its architecture read path covers the directory), `template-decision` `0.1.0` → `0.2.0`, `template-architecture` `0.1.0` → `0.2.0` (the section doubles as the ADR index), `template-context` `0.1.16` → `0.1.17` (the new optional key), `template-feature` `0.4.0` → `0.5.0` (link, never copy), and `propose` `0.2.0` → `0.2.1` (step 3 no longer routes every cross-cutting decision to the architecture-principles spec unconditionally).

Supersession is scoped the same way as placement: universal guidance keeps the in-place mechanic for an **embedded** decision and defers supersession inside a configured directory to the repo's index, so a repo whose convention is a superseding record is no longer denied by prose it installs.

No decision record moves: `specs/decisions/` stays as it is, and `CONTEXT.md`'s decisions index now states the threshold and the in-place supersession convention that universal guidance defers to it. `specs/architecture-principles.md` stops claiming decisions are never standalone files while this repo files them.
