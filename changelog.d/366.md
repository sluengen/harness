### Fixed — CONTRIBUTING's mutation section describes the tool that exists, and CONTEXT routes you to it (#366)

`CONTRIBUTING.md` is the one place in the repo that documents
`scripts/mutate.py`, and #365 shipped the liveness fork without touching it. It
went on presenting *an edit that changes no behaviour kills nothing* as a
sufficient signal — the belief #365 was built to remove, which cost #209 two
re-derivations and let an adversarial review prove a real BLOCKING finding with
invalid evidence. The section now describes `observe`, the `inert` outcome,
`SURVIVED (LIVE)` / `SURVIVED (UNPROVEN)`, exit `4` and the `observable` refusal
stage, and says plainly that killing nothing is not by itself evidence.

`CONTEXT.md`'s *Where deeper truth lives* now routes to the harness. Nothing did
before: `grep -rn "CONTRIBUTING" CLAUDE.md AGENTS.md CONTEXT.md skills/ commands/
agents/` returned zero hits, so a session with no prior exposure had no path to
the instrument at all. It lands in `CONTEXT.md` rather than in
`test-driven-development` or `code-quality` because those are **distributed**
guidance, copied into repos that have no `scripts/mutate.py`; repo-specific
tooling is exactly what `CONTEXT.md` is for.

The section is now **derived**, so it cannot go stale this way again. A new
`OUTCOMES` tuple in `scripts/mutate.py` is the module's own answer to "what can
this report", made load-bearing by an `EntryResult.__post_init__` invariant — a
classifier returning a sixth verdict raises on the first test reaching that
branch, so the tuple cannot drift from the literals it names. That matters
because `mypy`'s scope is `harness`, so `scripts/` is unchecked and a `Literal`
alias would be an unenforced list. `tests/unit/test_mutate_docs_currency.py`
then derives every obligation rather than listing it: the outcomes from
`OUTCOMES`, the survivor labels by calling `_label`, the table's keys from
`dataclasses.fields(Mutation)` (which is what puts `observe` under a predicate),
the exit codes by calling `exit_code`, and the refusal stages from the module
docstring's numbered list — cross-checked against every `RefusalError` call site
so the module's two accounts of itself cannot drift from each other first.

Each derivation carries a floor, because a check over a collapsed derived set
passes over nothing with no skip and no warning (#168/#169), and the span
extractor fails closed rather than falling back to the whole file — a widened
span would satisfy every check for the wrong reason.
