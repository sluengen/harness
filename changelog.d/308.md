### Changed — ssh-agent forwarding and the workspace mount move behind the host-platform seam (#308)

Two spawn concerns were macOS constants inlined in `harness.hostenv.spawn`: the
Docker Desktop bridge path the agent socket is mounted from, and the workspace
bind mount. Neither is wrong on macOS — both are the wrapper's proven behaviour —
but reusing them on another platform is *silently* wrong, and ADR 0012 makes
Windows-via-WSL supported.

`HostPlatform` gains `ssh_agent_forwarding()` and `workspace_mount()`, and
`WslHost` becomes its own provider overriding only those two. macOS is now the
only platform that mounts Docker Desktop's bridge and joins group 0; Linux and
WSL mount the socket liveness was probed against, so the probe and the mount can
no longer name different agents — under WSL the bridge reaches the *Windows*
agent while `SSH_AUTH_SOCK` names one inside the distro, which would have failed
every push against a healthy agent.

Path equivalence is asserted rather than assumed. `WorkspaceMount` carries the
host↔container mapping as one object whose `target` is emitted as the `-v`
target, `-w` and `HARNESS_WORKSPACE_ROOTS` — so those three cannot disagree — and
refuses a source that is not the resolved path of the repo the caller named. The
mount point stays `/workspace`: relocating it would rewrite the meaning of every
recorded `runs.worktree_path`, so the property ADR 0012 wanted is delivered as
mapping equivalence instead, with no ledger migration.

A repo on a Windows filesystem under WSL is **refused** with a named error naming
the path, the fstype and #313, before docker is touched — on both spawn paths.
Detection reads `/proc/mounts` rather than the `/mnt/` prefix, because `wsl.conf`
can move the automount root and an ordinary `/mnt/data` on ext4 must not be
condemned.

`serve`'s hand-inlined `:` check is deleted; the mount object owns that refusal
now, so there is one home for what a `-v` field may contain. Forwarding the agent
put a second value in that region — Linux and WSL mount `SSH_AUTH_SOCK` verbatim —
so `SshAgentForwarding` refuses a `:` in it too, with `UnsafeAgentSocket`, at
construction rather than at spawn time where the symptom names docker.
