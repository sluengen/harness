### Fixed — a cold docker build in the serve-socket tests no longer reds the gate (#357)

`tests/integration/test_serve_socket.py` built the verb image inside a
module-scoped fixture with no budget of its own, under the global 120s
pytest-timeout cap — which covers fixture setup. A cold build measures ~165s, so
all six tests ERRORed at setup with `Timeout (>120.0s)` and the gate went red on a
file the diff never touched. Warm, they passed. The weekly Docker prune on the
build host and every fresh CI runner both guarantee the cold case recurs, so this
was a scheduled failure rather than a flake, and it cost a full ~16-minute re-run
plus an authorship investigation each time it fired.

This is CAL-1110's defect arriving in a second module, but not CAL-1110's fix.
That one raised the whole module cap to 600s, which `test_docker.py` can afford
because its tests *are* the build. Here the build is incidental to six ~25s socket
tests, and a blanket 600s cap would give a genuinely hung socket test ten minutes
to burn. So the cap stays 120 and only the phase it is measured over changes: the
module declares `pytest.mark.timeout(func_only=True)`, moving pytest-timeout's
timer from setup + call + teardown to the test body alone, and the build carries
its own `subprocess.run(timeout=600)` — the same budget `test_docker.py` gives the
identical build of the same Dockerfile.

`tests/unit/test_timeout_budgets_coherent.py`, which already owned this invariant
family, gains two guards and grows a phase dimension. One pins that the build
budget and the per-test cap are distinct numbers correctly ordered, *and* that the
cap no longer covers setup — without that second half, a 600s budget under a
120s setup-covering cap is the original dead letter wearing a bigger number. The
other measures the claim rather than reading the flag's name: it unparses the
module's own marker from its `pytestmark` and replays it against a generated
module at 1/120 scale, asserting a 3s fixture survives a 1s cap while a 3s test
body is still killed. That runs in about four seconds and would catch a
pytest-timeout upgrade that changed what `func_only` means, which no amount of
reading the marker can.

The helpers behind both modules' guards moved from text search to `ast`. They walk
only the named fixture's own node, so they structurally cannot pick up the cheap
`docker info` probe's `timeout=15` that sits above it — the mis-parse an earlier
draft of this guard shipped, previously held off by a comment — and they read the
marker from the `pytestmark` assignment, so a mention in prose can never be read
as a declaration. The CI-job backstop now folds in `build + cap` as the
serve-socket worst case for a single item.

No production code changes, and none of the six tests' assertions move.
