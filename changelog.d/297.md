### Changed — `reclaim --stale` measures an attended run against `attended_idle_minutes`, not the wall clock (#297)

The sweep now selects its staleness threshold by the run's declared mode: `loop.wall_clock_budget_minutes` (110m) for an unattended run, the new `loop.attended_idle_minutes` (480m) for one started `harness start --attended`. A longer threshold, not an exemption — a session abandoned overnight is still reclaimed by morning, so the board self-heals and worktrees do not accumulate.

This closes the half of [ADR 0011](specs/decisions/0011-attended-run-spend-scope.md) that no measurement can fix. A session paused on a question to the operator touches none of the three liveness clocks the sweep reads, because a human thinking looks exactly like an orchestrator that died; the operator would answer and find the ticket reverted to Todo underneath them.

The three-clock idle rule is unchanged, and the mode is not a fourth signal — it selects the *value* all three clocks are compared against, including the tracker's. Because the attended threshold is the longer of the two, the mode can only ever spare a run, never condemn one. An explicit `--older-than` still overrides both modes, and a ticket with no resolvable run row has no mode to read and falls to the wall clock, the bounded default. `SweepOutput` reports the applied attended threshold as `attended_older_than` beside `older_than`.

`attended_idle_minutes` follows the other `loop:` knobs: configurable in `CONTEXT.md`, shipped in `templates/CONTEXT.template.md`, and backed by `DEFAULT_ATTENDED_IDLE_MINUTES` so a repo with no `loop:` block runs the decided 480.
