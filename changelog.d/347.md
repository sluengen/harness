### Fixed — a hung review engine is no longer retried into the same ceiling (#347)

`harness review` refuses a third engine attempt against a tree the engine has
already hung at twice, with exit 4 and `reason=repeat_engine_timeout`, before any
engine runs. Repetition against a byte-identical tree gathers no evidence: run
`01KZ67FRV3HZRZ8CMAHBYBP4QT` spent four consecutive ~725s `engine_timeout`
attempts at one SHA — ~48 minutes, roughly 44% of the unattended wall-clock
budget — for four identical answers, and finished only because the tree then
happened to change.

A new commit earns a fresh full attempt, since the guard keys on the reviewed
SHA rather than on the run. Rows recorded before this change carry no SHA and so
count as zero: a refusal that stops a run rests only on evidence the ledger
actually holds.

`ReviewRefusalEventData` gains an optional `reviewed_sha`, written by the
refusals raised at or after HEAD capture and omitted by the pre-HEAD ones, whose
recorded bytes are unchanged. The close gate is not widened — it binds on the
`verdict` key, which the refusal shape still omits.

The `engine_timeout` message no longer offers raising `engine_timeout_seconds`
as the default remedy. Here the engine hung rather than ran long, so a higher
ceiling would spend more per dead attempt and bring the wall-clock breaker
forward; the ceiling is now named only for an engine the ledger shows *finishing*
just past it. `engine_timeout_seconds` itself is unchanged at 720s.
