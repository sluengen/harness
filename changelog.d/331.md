### Fixed — the as-built record lands inside the tree the verdict certifies (#331)

Every surface that operated the as-built-record gate told the reviewer to write the record
*after* the verdict — "as the last commit on the branch before merge" in `agents/reviewer.md`,
the same in `commands/review.md`, `commands/ship.md`, `skills/spec-driven-development` and
`templates/feature.md`, and a *§3 Ship* record paragraph in `commands/build.md`. So the commit
that merged was never the commit that was reviewed, and never the commit the verify gate ran
over. That matters because a record is delivered tree content a link, generated-doc, or drift
guard can reject — and on the harness path it is refused outright, since `harness close` binds
the pass to a SHA and a post-verdict commit is exactly what `stale_review` rejects. The prose
instructed the agent to produce a state the gate exists to reject.

The ordering is now a named rule with one home: **final-evidence ordering**, in
`skills/review-discipline/SKILL.md`'s *Reviewer obligations*, beside the as-built-record gate it
strengthens. Draft the record, commit it into the candidate, *then* run the certifying gate and
decide. On a FAIL there is nothing settled to record; when the gate goes red because of the
reviewer's own record edit, the reviewer fixes its own edit (bounded to two attempts), never the
implementation. A deferral stays ordering-neutral.

Every other surface points at that home and carries no competing statement. The agent-led flow
gains the identity check the harness gets from its ledger: `/review` reports the `reviewed_sha`,
`/ship` refuses when HEAD has moved off it, and `/build` — which reviews a staged tree — pins the
committed tree against the `git write-tree` hash it reviewed. `commands/harness.md` gains the
record step it never had at all.
