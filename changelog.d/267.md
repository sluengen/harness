### Changed — the changelog moves to `changelog.d/` fragments, removing the conflict class (#267)
- Every ticket appended to `CHANGELOG.md`'s `[Unreleased]` block, so two concurrent runs conflicted at the same insertion point **by construction** — on a file whose correct merge semantics are "keep both lines". It cost one run two full rebase → gate → re-review → close rounds, then refused a close on two further ticks. A change now writes `changelog.d/<ticket>.md`, the filename being the primary key so a resumed run overwrites rather than duplicating; the release folds them in. `merge=union` was rejected on direct evidence — both sessions in that run had independently folded the *same* entries, which union merge duplicates silently.
- `scripts/changelog_fragments.py` holds `check` / `require` / `fold` together because the filename rule, heading grammar and closed category set are format knowledge each needs. **Two guards, cause and symptom:** `require` is the direct presence check but **abstains with a printed reason** where the merge base cannot resolve (shallow CI checkout, detached `promote` worktree), so the base-independent half is the CHANGELOG size bound, re-baselined from a headroom budget to a **may-not-grow ratchet** — the file no longer accumulates, so an append trips the gate wherever it runs. The retired byte soft-warning is re-homed rather than deleted, onto `changelog.d/` as a fragment-count bound plus a per-fragment byte budget, giving `RELEASING.md`'s long-standing 1,000-byte per-entry target teeth for the first time. `### None — <why> (#<ticket>)` is the exemption, a file in the diff rather than a flag, so a reviewer sees the claim. The two-pass between-release fold is replaced, not left describing a mechanism that no longer exists. `hook-guidance-freshness` 0.3.6 → 0.3.7 (registry 0.5.107 → 0.5.108).
