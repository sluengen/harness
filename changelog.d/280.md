### Fixed — a feature spec's `last_updated` is measured against git, not just required to exist (#280)

`specs/features/*.md` declare a `last_updated` date, and `tests/unit/test_feature_specs.py`
required the key while never reading its value. The field was decorative from the day it was
introduced: every record's date froze while the file changed underneath it, asserting a currency
that was false — worse than no date, because `feature_specs: true` makes these records the
contract.

A derived guard now reads the value. For every git-tracked `specs/features/*.md`, the declared
`last_updated` must be no older than the author date of the last commit touching that path. The
subject set comes from the tracked tree rather than a hand-written list, so a fifth feature spec is
covered the moment it is committed, and a non-vacuity check keeps an empty derived set from passing
as a measurement. `worktree-lifecycle.md` — the one record still stale — is corrected in the same
change.

The comparison is against the *author* date of the last **committed** change: it is the one date a
writer can know while typing the value, and it survives the merge that lands it. A path git reports
no commit for (staged but never committed, or a shallow clone) skips with a printed reason instead
of reddening the gate for a reason unrelated to currency.

`templates/feature.md` now states what the field means and when it moves, so a consuming repo with
`feature_specs: true` gets the rule rather than only the key.
