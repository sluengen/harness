### Fixed — `harness design` collects its design from a file, so one dropped character no longer discards it (#294)

The design engine's only output channel was a single final `SUBMIT: <json>`
line on stdout — `review`'s contract, inherited by a verb whose payload is a
14–17 KB Markdown document rather than a fixed 100-character verdict. Escaping
a document onto one physical line leaves no structural landmark anywhere in it,
so the model has to carry "I still owe a `}`" across thousands of output tokens.
Measured on this repo's ledger: `design` lost **12.5% of attempts** to the wire
format (`malformed_submit` 8, `no_submit` 2, of 80) against `review`'s **0.24%**
(1 of 423). One run lost 12m44s of Opus and a complete 31 KB design because a
single closing brace never arrived.

The verb now allocates a file in a fresh directory **outside** the worktree,
grants the engine write capability for that one path, and reads the design back
from it — no escaping, no bracket depth, no single-line constraint, and no size
ceiling. The directory is removed on every path, so nothing the design stage
does can trip `close`'s `dirty_worktree` gate.

That grant replaces `--permission-mode plan`, and is the narrower of the two:
plan mode was a cooperative, mode-level restriction while the container's
workspace mount stayed read-write, whereas the engine now refuses every
capability by default and holds one rule-level exception. Verified against the
real CLI in the `harness:dev` container — the design path was written, a probe
write into the worktree was refused, and the worktree stayed clean.

A **stdout fallback** (the design between two nonce-marked lines) is the second
channel and doubles as a detector: no test can spawn a real `claude`, so a
permission-config regression would otherwise take the stage from working to
producing nothing, invisibly. The `design` event records which channel delivered
(`channel`) and how long the design was (`design_chars`), so that regression
reads as a measured degradation on `harness stats` rather than as silence. The
fallback also tolerates a missing closing marker, so an engine that finishes and
drops its final line still delivers.

The two failure tags `no_submit` / `malformed_submit` are replaced **here** by
one, `no_design_output` — a file is written or it is not. `review`'s SUBMIT
contract, which fits its payload, is untouched.

The prompt also states a length target (18,000 characters, above every design
that has landed and well below the 31 KB outlier), stated to the engine and
measured via `design_chars` rather than enforced — rejecting an over-length
design would reintroduce the discard-on-violation this change removes.
