### Fixed — `harness design` collects its design from a file, so one dropped character no longer discards it (#294)

The design engine's only output channel was a single final `SUBMIT: <json>`
line on stdout — `review`'s contract, inherited by a verb whose payload is a
14–17 KB Markdown document rather than a fixed 100-character verdict. Escaping
a document onto one physical line leaves no structural landmark in it, so the
model must carry "I still owe a `}`" across thousands of output tokens.
Measured on this repo's ledger: `design` lost **12.5% of attempts** to the wire
format against `review`'s **0.24%**. One run lost 12m44s of Opus and a complete
31 KB design because a single closing brace never arrived.

The verb now allocates a file in a fresh directory **outside** the worktree,
grants the engine write capability for that one path, and reads the design
back — no escaping, no bracket depth, no size ceiling. The directory is removed
on every path, so the stage cannot trip `close`'s `dirty_worktree` gate.

That grant replaces `--permission-mode plan` and is the narrower of the two:
plan mode was a cooperative, mode-level restriction while the workspace mount
stayed read-write, whereas the engine now refuses every capability by default
and holds one rule-level exception. Verified against the real CLI in the
`harness:dev` container — the design path was written, a probe write into the
worktree was refused, the worktree stayed clean.

A nonce-marked **stdout fallback** is the second channel and doubles as a
detector: no test can spawn a real `claude`, so a permission regression would
otherwise take the stage from working to producing nothing, invisibly. The
event records which channel delivered (`channel`) and the design's length
(`design_chars`), so that regression reads as a measured degradation on
`harness stats` rather than as silence. The fallback also tolerates a missing
closing marker, so an engine that finishes and drops its final line still
delivers.

`no_submit` / `malformed_submit` are replaced **here** by one tag,
`no_design_output` — a file is written or it is not. `review`'s SUBMIT
contract, which fits its payload, is untouched. The prompt also states a length
target (18,000 characters, above every design that has landed and well below
the 31 KB outlier), measured via `design_chars` rather than enforced.

The engine is no longer described as read-only anywhere: eight surfaces still
said so, including `CONTEXT.md`. A new guard derives that claim from the tracked
tree rather than trusting a list of the places it was made.
