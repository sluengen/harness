### Fixed — the distributed hooks now declare CommonJS, so they survive an ESM consumer root (#302)

Node resolves a `.js` file's module type from the nearest `package.json` walking
up. The five guidance hooks shipped as bare `.js`, so in a consuming repo that
walk reached *that repo's* root — and where it declares `"type": "module"`, all
five CommonJS hooks were parsed as ESM. Four died on their first `require()`;
`prompt-guard.js` swallowed the failure inside `readStdin`'s `catch` and exited 0
with an approving `{"continue": true}` having scanned nothing, leaving the
prompt-injection scanner silently disarmed.

`hooks/package.json` (`"type": "commonjs"`) terminates the walk above the
scripts. It is a registry entry, so `/update-guidance` or a re-bootstrap carries
it into a consuming repo — a consumer that does not update keeps the old
behaviour.

`BOOTSTRAP.md` also gains the Windows workaround: without Developer Mode git
writes each committed `.claude/*` symlink as a plain text file, so the whole
guidance surface silently disappears. Step 3 now records the junction
substitution and the `--skip-worktree` plus trailing-slash-ignore pair that keeps
`git add .` from committing a junction's contents over the symlinks.

Reported by an external contributor onboarding nano-erp on Windows.
