### Fixed — the retired-surface doc guard bans a usage, not a phrase (#355)

The live-doc guard banned the bare string "harness run", so English prose naming
a run of the harness matched as if it were the retired CLI command. That turned
`origin/dev` red: with `harness review` refusing a non-zero gate, no ticket could
reach review until the sentence was reworded.

The banned terms are now split by whether English can produce them. The
invocation terms — the ones spelled out of ordinary words — are scanned only in
**command context** (fenced bodies, inline code spans, and 4+ column indented
blocks for markup and module docstrings; the whole text for `entrypoint.sh` /
`Dockerfile` / `docker-compose.yml`, where every line is a command). Indented
blocks count because the CAL-699 drift the docstring guard exists for was an
indented listing with no backticks at all — a backticks-only rule would have
deleted that guard's own founding coverage. The artefact terms —
`harness.{engine,nodes,dispatch,workflow}` and `workflows/*.yaml` — are
identifiers no sentence produces, so they keep firing anywhere. The Python
docstring guard now shares the same term tuple instead of transcribing it, so
the defect cannot live on one function away.

Narrowing a guard can disarm it, so the controls are structural: every
invocation term keeps a command-context sample proving it still fires,
parametrized over the production term tuple with a bijection floor so neither
adding nor deleting a term slips through unguarded; per-doc injection probes
assert equality with the injected hit, which also proves each doc is clean
today. Two extraction invariants have their own controls — a sentinel join, so
two abutting fences cannot fuse into a hit neither contains, and spans that
never cross a newline, so one unpaired backtick cannot launder a passage into
code.

Accepted trade: a retired command named in bare prose now escapes the guard.
