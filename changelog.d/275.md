### Changed — the size-marker guard covers every tracked Python tree, not just production (#275)

The mechanical size guard scoped to `harness/` and deferred `tests/` in prose. By
the time that deferral was revisited the test tree held 14 files past the
declarative ceiling with no recorded size decision, and `scripts/` had never been
in scope at all. The guard now reads a ceiling-per-tree map — `harness/` and
`scripts/` at the 500-line hard limit, `tests/` at Part B's 750-line declarative
ceiling, derived as 1.5x rather than typed — and a companion check derives the set
of tracked Python trees from the git index so a new one cannot become a silent
blind spot. The 14 over-ceiling test modules each carry a `# size:` marker naming
what splitting would scatter; `test_cli_reclaim.py`'s names #274 as its tracked
split.

`templates/size-guard.md` (0.2.0 → 0.3.0) gains the matching adopt guidance: scope
every source tree, give the test tree the declarative ceiling, and expect the first
run to go red. Its shipped `DECLARATIVE_GLOBS` default stays empty — the inert
default is a deliberate contract, so this is guidance, not a defaults change.
