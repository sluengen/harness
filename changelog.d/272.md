### Fixed — a `CONTEXT.md` watchlist note may no longer contradict the file it describes (#272)
- The `architecture_watchlist` entry for `harness/cli/close.py` claimed the file *"retired the `# size:` justification (now ~450 lines)"* while it stood at 531 lines carrying a marker #263 had re-added, and the `review.py` entry never learned about #262's `review_telemetry.py`. Three tickets touched the two gravity wells after the entries were last hand-edited and none refreshed the prose, so the record a builder reads to judge whether their change grew the well was wrong in the one direction that matters — it understated both the size exemption and the decomposition. The in-file `# size:` markers, the half that *is* checked at build time, stayed correct throughout: the two sources of truth for one fact had diverged, and the one a reader hits first was the stale one.
- The arm guards that already exist (CAL-1014, CAL-1139) pin *membership* — that each well is listed and that its note names its concern mix — and never open the file the note describes, so a note could say anything about it and stay green. Two guards now read the note against the tree: a marked file may not be described as having retired its marker, and a note must name every `<stem>_*.py` module extracted out of it. Both **derive** rather than list — the sibling set comes from `git ls-files`, not a literal, so the guard cannot rot the way the prose it guards did, and the entries drop their line count entirely rather than restating a number that was accurate when written and is the thing that went stale. A third assertion pins the anti-vacuity case a rename would otherwise open: every glob must resolve to a tracked file, since a measuring test that can silently measure nothing is the failure mode this ticket is about.
- The retirement detector is a tripwire for one falsifiable claim, not a semantic judge, and its bounds are pinned by example both ways — including this change's own replacement wording as a no-match case. `split out` and `extracted` are deliberately not retirement verbs: recording an extraction is what the note is for.
- **Departure from the run's design, recorded:** the design left the extraction-naming criterion to reviewer read, on the grounds that the generalized form couples prose to import structure. The guard shipped instead derives from the `<stem>_*.py` filename convention via `git ls-files`, never from imports, so modules the file merely imports are outside it by construction — and a stated acceptance criterion gets a measuring test rather than prose. The accepted cost is a sibling that is not an extraction still having to be named; the module docstring carries the full reasoning and its boundary against #273.
