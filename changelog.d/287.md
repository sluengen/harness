### Fixed — a commit with no ticket by design gets a stated changelog exemption, not an accidental one (#287)
- `require()` demanded a `changelog.d/<ticket>.md` whose stem matched a tracker id, and two commit classes have no ticket to name: an `/assess` report, which `commands/assess.md` step 3 already exempts from the merge gate, and a `/propose` output. Both reached a green gate **only** because `require` abstains on an empty diff — i.e. by being gated *after* pushing, at a moment the guard could see nothing. Same shape as #278's abstention trap: a guard whose only passing path for a whole class is "the diff was empty" is not covering that class, and it flips to a hard failure the instant someone gates before pushing, which is exactly where a careful builder gates. Observed twice — the 2026-08-01 assessment report, and the ADR 0012 proposal commit, which is confined to `specs/` and so would not have been covered by the `assessments/`-scoped fix originally preferred.
- The fix is **stem-shaped, not path-shaped**: a reserved `changelog.d/no-ticket-<slug>.md` carrying `### None — <why> (no-ticket-<slug>)`. A path-scoped exemption covers only the first instance and needs a per-path process rule invented before the guard has anything to agree with — `commands/assess.md` supplies one for `assessments/`, nothing does for `specs/proposals/`. A `--allow-no-fragment` flag was rejected outright: the exemption's entire enforcement is that it is a **file a reviewer sees in the diff**, and a flag is invisible at review.
- Three invariants contain the class. The stem is lowercase, so it is **disjoint from `_TICKET` by construction** — that admits only digits or an uppercase Linear key, so `27O.md` and `cal-1204.md` still match neither and the widening loosens nothing for the ticket class (proven by mutation). A no-ticket fragment may carry **only** `### None`, which keeps it out of released history and is why `fold` needed no change — it is never `releasable`, so `_sort_key`'s `int(...)` never sees a non-numeric stem. Its heading id is bare, since `#` means "GitHub issue" and there is none.
- `require`'s presence detection is **unchanged**; only the stated reason is new, and a diff carrying both fragment kinds still prints the plain wording. The abstention arms are untouched and asserted to stay distinguishable: an unresolvable base still abstains **with** a no-ticket fragment present, because "I cannot see the base" and "this change is exempt" are different claims, and collapsing them would hide a misconfigured base behind a green gate. This removes the *reliance* on abstention, not abstention.
- The exemption stays an honour system, by design. `require` never tied a fragment to the change it accompanies — `changelog.d/999.md` already satisfied the gate for any diff — so the new stem opens no bypass that was not already open. What changes is that the honest author now has a filename they may use.
