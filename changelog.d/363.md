### Added — `harness review` runs the mutations the reviewer proposes (#363)

A mutation table certifies only what its author thought to mutate, and the author
is the person being reviewed. The one party positioned to be an independent
counterparty on that table was, until now, the one party that could not run
anything.

The review engine still runs read-only, byte-for-byte the command it ran before.
What is new is that it may **propose**: up to `loop.probe_max_entries` mutation
entries on the same `SUBMIT:` line, each declaring the tests it must make fail.
The verb creates a detached throwaway worktree at the reviewed SHA, screens the
proposal against it, runs the entries through `scripts/mutate.py` under
`loop.probe_budget_seconds`, and hands any survivor to a second engine pass where
it may become a finding prefixed `[probe:<id>]`.

Three properties are enforced rather than intended:

- **A probe must predict its outcome.** An entry that kills nothing and one that
  breaks collection are each a failure of *the entry*, never a survivor and never
  a finding — which is what stops the vacuity this repo pays for from relocating
  into review. A survivor with no observable is carried as a *lead*; only one
  whose observable moved is recorded as demonstrated.
- **The budget is a bound.** The count cap truncates and names what it cut; the
  time ceiling kills the subprocess and is clamped to the *configured*
  `engine_timeout_seconds`, so one review's added cost cannot exceed one engine's.
  The pytest selection is verb-owned and not proposable.
- **Nothing the engine produces reaches the reviewed SHA.** The probe tree is a
  different directory, and the run worktree is snapshotted before the engine gets
  control and re-checked after; a change refuses exit 3
  `reason=run_worktree_mutated`. Honest limit: it sees what git sees, not a write
  inside a gitignored path. `close`'s two conjuncts remain the enforcement.

Every failure degrades — the stage records `probe_status` and the first pass's
verdict stands. `probe_max_entries: 0` disables it and restores the prior prompt
byte-for-byte. In-container the verb's image carries no test toolchain, so the
stage honestly records `unavailable`; a host-side install runs it.

`scripts/mutate.py` regains the `--json` report #360 dropped for want of a
consumer. The verb reads that, never `render()`: deriving a verdict from a human
summary is the defect #207 is.
