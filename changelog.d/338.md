### Changed — `defer` and `release` are one seam, and the tracker is their only record (#338)

`harness defer` and `harness release` were two CLI modules carrying the same
shell twice over: resolve the tracker and the configured queue, validate
membership, translate boundary errors, run three mutations. That shell now has
one home, `harness/cli/held_ticket.py`, and each verb module keeps only its
Typer signature, its exactly-one-of `--text`/`--file` rule, and its own output
line. The queue-membership gate — the only bound between an operator-supplied
identifier and three authenticated writes — can no longer be present in one
verb and missing in the other.

Neither verb writes the ledger any more. Both used to manufacture a terminal
`runs` row purely to satisfy the `events` foreign key and hang one event off
it, which made a triage write indistinguishable from a build run in every
ledger-backed view while nothing — not the close gate, not reclamation, not
recovery — ever read it. The tracker issue is the audit trail: the comment or
resolution, the hold label, the assignment, project membership. Historical rows
are untouched and stay readable; `defer` and `release` remain in `EventType`
with their payload models so existing ledgers parse without migration, and
`harness stats` still reports the counts it already has.

A write bundle that fails part-way now reports **which step** failed, as
`step` on the error JSON (`comment`/`label`/`assign`, or
`resolution`/`label`/`unassign`), and never reports success.

The public CLI is unchanged — same names, flags, exit codes, refusal reasons
and tracker-less no-op. Two pieces of surface are now deprecated and inert: the
JSON `run_id` is always `null` (a held-ticket transition creates no run), and
`--db` is accepted but opens no database. Both are retained so an existing
orchestrator's argv and envelope parsing keep working, and are removable only
in a breaking CLI release.

One capability is lost rather than moved: #264's `duration_ms` telemetry for
these two verbs went with their events, so a held-ticket transition's latency
is no longer measured anywhere. It was only ever readable through the synthetic
row this change deletes.
