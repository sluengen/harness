### Added — a surviving mutation must prove it changed behaviour (#365)

`scripts/mutate.py` could not tell an **inert** mutation from a **weak guard**:
both reported `survived`, and the module said so — *"the no-op direction is
self-limiting."* That is a habit, not a mechanism, and #209 is what it cost.
Mutating the gate's parallel stage from `-m "not docker"` to
`tests/unit -m "not docker"` lands exactly once and passes every refusal #360
has, but `tests/integration/` holds only docker-marked modules, so both spellings
collect the identical 4,826 tests. It changed nothing and reported SURVIVED. The
sharper cost was the other direction: that tick's adversarial review used a no-op
mutation as its evidence for a real BLOCKING finding. The finding was right and
its proof was invalid, independently.

An entry may now declare a **behavioural observable** — `observe`, argv run
inside the tree. A survivor is classified by it: digests differ → `survived`,
rendered `SURVIVED (LIVE)`, now the only thing SURVIVED can mean once an
observable is declared; digests match → **`inert`**, a new outcome whose exit
code `4` dominates `1`, because an inert entry means the report cannot be read as
evidence at all; no observable → `SURVIVED (UNPROVEN)`, with a line saying
nothing has shown the mutation was live and naming `observe` as what to add.

`observe` is argv appended to `sys.executable`, never a program name and never a
shell string. That is the keystone: it keeps the one binary this module may spawn
pinned by the AST guard #360 shipped, so an observable gets exactly the trust the
tree's own suite carries and no more.

It is checked before any write, in an `observable` refusal stage after
`prediction` — a mistyped node id stays the cheaper defect and is not paid for at
observable prices. Each distinct probe (deduplicated) runs **twice on the
pristine tree**: two differing runs refuse, since a nondeterministic probe would
differ against every mutation and certify them all live; a nonzero exit refuses,
since a broken probe breaks identically on both trees and would report every
entry `inert` — an accusation against the table made on no evidence. A probe that
cannot run raises `RunnerUnavailableError` (exit 3), the infrastructure-versus-tree
split the baseline already makes.

The mutated observation runs inside the existing `try`, after the suite and
before the restore, and **only for a would-be survivor**: an entry that killed
something is manifestly live, and a narrow probe must not downgrade a real kill.
One that could not complete is `errored`, never `inert` — reading a missing
measurement as a measurement of nothing is how a harness lies in your favour.

No captured output reaches the report or the refusals; digests, counts and
durations only. They print the argv instead.

`killed`, `mispredicted`, `kills` set equality and the existing refusal ordering
are untouched, proven by `tests/unit/test_mutate.py` passing unmodified.
