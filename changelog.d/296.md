### Changed — the review wall-clock breaker applies to unattended runs only (#296)

`harness review`'s per-run wall-clock breaker measured raw age since `started_at`,
so an attended session's elapsed time included however long the operator took to
answer a mid-run question — time during which the run spent nothing. Past the
budget the finished work became un-certifiable and could not close.

The clock now applies to unattended runs only ([ADR 0011](specs/decisions/0011-attended-run-spend-scope.md)).
`evaluate_breakers` takes the mode as a keyword argument and skips **that check
alone**; `review` resolves the mode from the run row's `inputs_json` through the
shared `resolve_attended` helper #295 shipped.

Three properties bound the change:

- **The cycle ceiling stays unconditional.** It bounds the fix loop itself, which
  an operator's presence does not make cheaper. With both breakers eligible the
  reported reason is still `review_cycle_ceiling`, in either mode.
- **The exemption is never acquired by omission.** `attended` defaults to `False`,
  so a caller with no view of the mode inherits the bounded behaviour, and only
  the literal JSON `true` on the run row reads back as attended. A corrupt or
  hand-edited ledger can make a run more bounded, never less.
- **Neither threshold moves**, and no reason tag, exit code or output field changes.

`reclaim --stale` still applies the same threshold to every run; aligning the
sweep's scope is #297.
