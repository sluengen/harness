### Fixed — a hook that falls open now says so on stderr (#303)

The five distributed hooks fail open by design — a hook that blocks on its own bug
wedges every `Bash` call or every `Write` in the session — but they did it
*silently*. An unreadable payload became `{}`, which flows into `main()` as
`tool_name === ""`, so a parse failure and a deliberate pass-through produced
byte-identical output. That is what let #302 hide: in an ESM consumer repo
`prompt-guard.js` swallowed its own load failure and reported success for an
unknown length of time, with the install record still saying the prompt-injection
scanner was there.

stdout, the exit status and the blocking contract are unchanged. A hook that falls
open now writes one line to stderr — `[<TAG>] fail-open: <reason>: <cause>`, the
tag derived from the filename — built from hook-owned constants and `err.message`
alone. It never echoes the payload: that is attacker-influenced text, and a
scanner repeating the injection it failed to read would re-inject it into the
transcript through the channel added to report on it. The cause is
whitespace-collapsed and truncated, so a crafted payload cannot forge a second
notice or flood the transcript.

`prompt-guard.js` also gains the top-level `main()` wrapper the other four already
had, so the five agree on a posture rather than differing by accident.

Best-effort swallows stay silent — debounce markers, the context-monitor state
cache, `statSync` on a missing transcript, `workflow-guard`'s `git()` returning
`""`. The two classes are told apart by a rule derived from the source rather than
a list of line numbers: a `catch` whose `try` body reads stdin (`readFileSync(0`)
or invokes `main()` is on the hook's decision path and must report; every other
`catch` is best-effort and must not. A swallow site added later is classified on
the shape of what it guards, so it cannot land unjudged.

Rejected a shared `hooks/fail-open.js`: it would be a load-time dependency between
two separately-installed files whose own failure is the class being reported on,
and it would move `prompt-guard.js`'s only `require` out of `readStdin`'s `try`,
turning its ESM failure from "approve silently" into "crash before writing
stdout" — the contract change this ticket forbids.
