### Changed — a seam extraction must refresh the watchlist entry it invalidates (#273)
- `review-discipline`'s **Architecture watchlist** check gains one clause: when the recorded `Watchlist trigger` outcome is a seam extraction, also confirm the matching `architecture_watchlist.files` entry's own descriptive comment still names the file's current decomposition and size state. A stale one folds into the Medium finding the bullet already grades — no new severity, no second checklist item.
- The gap it closes sat between two adjacent bullets. **Architecture watchlist** checked that a *decision* was recorded; **CONTEXT.md currency** checked the `stack` / `commands` / `layers` blocks on a trigger list that never reaches `architecture_watchlist`. So a change could record its trigger correctly, pass both, and leave the entry describing a decomposition the extraction had just replaced — which is what produced #272, including an entry stating the direct opposite of the truth. The clause is attached to the watchlist bullet rather than widening the currency bullet's trigger list, because that narrowness is load-bearing and says so in its own text ("it is not 'read `CONTEXT.md` every time'"); the watchlist bullet already has the changed file set in hand, so the confirmation costs nothing extra to run.
- The clause is deliberately bound to the *extraction* outcome, not to every watchlist touch: a recorded deferral carves nothing out, so the entry's decomposition prose is not invalidated. It also asks for the size *state* rather than a line count — #272's entry pinned "~450 lines" and that number is the half that rotted, so requiring a reviewer to keep one true would re-file the same defect as an obligation.
- Four guards pin it, anchored to the bullet rather than matched over the file: the tokens asserted (`entry`, `decomposition`, `size`) were each confirmed absent from the pre-change bullet, so a guard keyed on them cannot be green against the unmodified prose; the binding test rejects a clause that co-locates the words without tying them to the extraction outcome; an anti-vacuity test fails if the slicer over-runs into the neighbouring bullet, whose own `CONTEXT.md` and stale-entry prose would otherwise satisfy the tokens; and one pins the no-op scope sentence as still terminal, so a repo with no `architecture_watchlist` stays out of scope for the clause too. The slicer is imported from the guard that owns the bullet rather than recopied.
- This is the universal half. This repo also mechanizes the same concern locally against its own `CONTEXT.md` (#272), but no consuming repo is assumed to carry such a guard — and mechanizing the checklist further is out of scope by design: the watchlist discipline is reviewer judgement.
