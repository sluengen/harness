### Added — tracker neutrality is a source-tree invariant, not review memory (#339)

No module under `harness/cli/` may name `harness.linear` or `harness.github` — not
as an import, not as a name imported from one, not as an attribute chain into one.
`harness.tracker`, `harness.tracker_errors` and `harness.tracker_queue` stay
unrestricted: the rule is a denylist of backends, so a future seam-side module
cannot be forbidden by omission.

A verb that constructs its own backend client acquires a second, ungated path to
`LINEAR_API_KEY` / `GITHUB_TOKEN` and gives backend selection a second source of
truth. That is what made `promote escalate` demand the Linear key in a repo
configured `tracker: github` until #328 — the escalation terminal was unreachable
on the backend this repo dogfoods. The guard makes that state fail the gate rather
than the operator's board.

The scan derives its subject from the **tracked** `harness/cli/*.py` set, so an
abandoned worktree parked under the package cannot read as living source (#215),
and it reads the AST rather than the text — four CLI modules name a backend client
in prose legitimately, so a grep-shaped guard would be red on a clean tree. The
backend vocabulary is itself pinned to `harness/tracker.py`: a third backend wired
into `tracker_client` fails the guard instead of slipping past a stale literal.

`promote.py`'s narrow one-file detector is superseded and removed — two detectors
of one rule drift, and the weaker one goes green while the stronger is degraded.
Its named #328 regression survives as a pin beside the tree-wide scan.

Dynamic access (`importlib.import_module`, `getattr`) is a stated non-goal: this
is a guard against drift and accident, not an adversarial sandbox.
