### Changed — the loop knobs carry one value in three places (#291)

`DEFAULT_ENGINE_TIMEOUT_SECONDS` moves 600 → 720, matching what this repo has
configured since 2026-07-30 and the treatment the other two loop knobs already
get. A repo with no `loop:` block now resolves the ceiling this repo's ledger
evidence actually produced, not the one it replaced. The retune only widens an
unconfigured ceiling, so no run that used to succeed can now fail, and a repo
that already set the key is untouched.

`templates/CONTEXT.template.md` gains the `loop:` block it never shipped. Every
bootstrapped repo previously ran on the code defaults with nowhere to see or set
them — while `harness design`'s engine-timeout failure told them to *"raise
`engine_timeout_seconds` in CONTEXT.md's `loop:` block"*, remediation naming a
block their CONTEXT.md did not have. The block ships all three keys as bare
integers equal to their constants; the comment says why a `{e.g. …}` placeholder
would be wrong there (the reader matches digits only, so a placeholder falls
back silently while reading to a human as though it were set).

An anti-drift guard (`tests/unit/test_context_template_loop_block.py`) pins all
three places — constant, this repo's `CONTEXT.md`, and the template — against
the constants, which are the source: `load_loop_budget` never reads the
template, so the other two are copies. The knob table is derived rather than
restated (the constant's name is `DEFAULT_` + the key upper-cased), so a fourth
knob is covered the day it is added, and the parse is the runtime reader's own
regex rather than a copy of it.

`CONTEXT.md`'s `engine_timeout_seconds` rationale no longer claims the code
default is deliberately held apart from the configured ceiling — they are now
the same number. That correction is measured, not hand-checked: the guard
derives the relation from the two values and then requires the sentence naming
the constant not to deny it, so a reword cannot quietly restore a false claim.
The one-knob-two-workloads mis-fit the old sentence also named is unchanged and
still goes to `/propose` separately.
