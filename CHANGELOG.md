### Changed — /build and /build-codex: convergence-gated loop, preserve-on-abandon teardown
- **`commands/build.md` → 1.1.0** and **`commands/build-codex.md` → 1.1.0**. Two fixes from live runs.
- **The hard 3-iteration cap is gone.** Aborting at round 3 was killing runs that were genuinely converging — fixing issues exposes new ones, and many landed at round 4–5. The first 3 iterations still run unconditionally; after that, a **convergence check** runs before every further iteration. Converging (findings shrinking, anything new is genuinely new) → keep going; not converging (same items recur, resolved items re-raised, no net progress) → abandon. The orchestrator records one line of reasoning per check so the call stays honest.
- **Abandon no longer destroys the work.** The old "Exhausted" path tore down the worktree, discarding a partial implementation and any chance to investigate why the run failed. Renamed to **§4 Abandoned**: it now commits the work to the run branch, **pushes it**, comments the branch on the ticket, and **leaves the worktree and branch in place**. The success path (§3) is unchanged — commit, merge, push, tear down as before.

### Changed — load-bearing rules survive an un-walked reference chain
- **Root cause (transcript audit).** In a live harness run against a standard repo, the implementing agent read `CLAUDE.md` → `AGENTS.md` → `CONTEXT.md` (it follows the explicit "Read both" in `CLAUDE.md`) but opened **zero skill files**, and shipped a query-count optimisation with no test that counts queries. Every skill reference read "following `test-driven-development`" / "see `code-quality`" — which a goal-directed agent parses as a *methodology label it already knows*, not a *file to open*. The rules that would have caught it sat one un-taken hop away.
- **Inline the floor where the agent provably reads.** `process-standard` → 0.3.0 and `process-harness` → 0.3.0 expand the one-line "no completion claim without fresh evidence" into a three-part non-negotiable floor, written out in full so it binds even with no skill file open: test-first; **a measurable criterion needs a test that measures it**; no completion claim without fresh evidence. `start` → 0.2.0 turns Step 5's "following X" into an explicit "open and read `skills/test-driven-development.md` and `skills/code-quality.md`". `dev` → 0.2.0 makes "Load these skills" an imperative "Read these skill files before building" and forbids shipping a measurable criterion without a measuring test. `code-quality` → 0.2.0 records the rule in Part C (its canonical home) with a claim/evidence row.
- **The general rule, not just queries.** A criterion stated as a quantity — query count, response time, payload size, error rate — is proven only by a test that measures that quantity and asserts the bound; a structural change is not evidence. Stack-neutral; the measurement tool stays repo-specific (`CONTEXT.md`).

### Changed — spec model: reference specs + embedded decisions
- **Decisions now live in the spec they govern** — no standalone ADRs, no `decisions/` folder. A feature decision embeds in its feature spec; a cross-cutting one in the architecture-principles spec.
