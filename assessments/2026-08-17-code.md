## Findings

### CODE-1 — The as-built record's `git log --follow` measurement is false on today's tree — blocking, small

**What:** `specs/features/guidance-system.md` states, present-tense: "Measured rather than assumed: that command returns 16 commits against the plain form's 22, and all six it drops are reconciliation merges." Measured this pass: `git log --follow -- specs/features/guidance-system.md` returns **37** commits against the plain form's **49** — twelve dropped, not six. (The conclusion survives: all twelve dropped commits were verified to be merges, and the file has still never been renamed. The numbers are what falsified.) This is the third consecutive instance of the same class in this file: the #447 review found a false claim about the distributed walker's marker regex, and the #445 review found a false claim about an app-only path surviving the guards. The record is the contract this repo tells every agent to read before changing behaviour, so a false measured sentence in it is the tree contradicting its own contract today.

**Where:** `specs/features/guidance-system.md:443`.

**Why:** `spec-authoring` → *Grounding* (a recalled fact reflects what was true when it was written) and its as-built rule at `skills/spec-authoring/SKILL.md:105` — "a prose list with no derivation is a claim nothing measures, and it goes stale at the commit that adds the next member." An unanchored present-tense count goes stale at the next commit touching the file, by construction.

**How:** Rewrite the one sentence so it cannot falsify: either anchor it ("at `d525134`, that command returned 16 against 22") or restate it as the invariant that actually matters ("`--follow` drops only reconciliation merges, whose content reaches the reader through the commits they merged; the file has never been renamed") with no counts. CODE-INSIGHT-1 is the class-level prevention.

### CODE-2 — Twelve token values are hand-copied as hex literals on the landing page, outside the block the drift gate certifies — non-blocking, small

**What:** `docs/index.html` carries 82 hex-literal occurrences (52 distinct values) outside the generated `design-tokens:begin…end` block, and **12 of those distinct values are byte-duplicates of live token values** in `design/03-tokens/tokens.json` — e.g. `#23348f` (`--product-ink`) hardcoded 4×, `#d97706` (`--quality`) 3×, plus `#3b5bdb`, `#e9edfd`, `#fdf1df`, `#7c3aed`, `#4c1d95`, `#0f9d6e`, `#0a5e44`, `#8a4b06`, `#f1eafd`, `#ffffff`. The gate (`scripts/verify.sh:63` → `scripts/build_design_tokens.py --check`) certifies only that the generated `:root` block matches `tokens.json`; a token value change would update the block and leave every hand copy silently stale. History note, so this does not read as refiling fixed work: the 2026-08-04 pass found this as its CODE-3 (the count was 82 then too — byte-identical today), filed it as #335, and #335 was closed `NOT_PLANNED` in the ADR 0015 bulk sweep with the rationale "belongs to a retired subsystem" — but the design layer, the page, and the drift gate all survived the teardown (ADR 0015 does not mention the ticket or the token guard), so the subject is live and the closure rationale does not apply to it.

**Where:** `docs/index.html:132,147,213` (CSS rules using `#23348f`/`#eef1fb` where `var(--product-ink)` exists), `docs/index.html:264,272,287,298` (inline-SVG `fill`/`stroke` attributes using `#d97706`, `#fdf1df`, `#23348f`); the certified block is lines 21–29.

**Why:** `design-system` — the page is the repo's own design-system consumer and must use its tokens rather than degrade them; `code-quality`'s sync-critical-second-copy class — duplicated knowledge with no correspondence guard drifts silently, and here the guard's boundary is exactly what makes the drift invisible.

**How:** Replace the 12 duplicated values with `var(--…)` references (for the SVG presentation attributes, move `fill`/`stroke` to `style="fill:var(--quality)"` or a CSS rule). The remaining ~40 distinct literals are page-local shades with no token identity; tokenising them is a separate design decision, not this fix. CODE-INSIGHT-2 closes the class.

### CODE-3 — Shared test helpers have no neutral home: 132 repo-root copies, 20 local section-slicers, and 30 modules importing from sibling test modules — non-blocking, large

**What:** Three accumulations of the same shape across `tests/unit/`. (1) 132 of ~147 modules each define their own repo-root constant, in three spellings — `_REPO_ROOT = Path(__file__).resolve().parents[2]` ×80, `REPO_ROOT = Path(__file__).resolve().parents[2]` ×35, and the unresolved `REPO_ROOT = Path(__file__).parent.parent.parent` ×17 (the unresolved form is the frame-mismatch hazard the repo's own craft reference names: an unresolved root compared against a git-printed resolved path is a latent constant-true/false). (2) 20 modules define a local `def _section(` slicer under five incompatible signatures — `(text, header)`, `()`, `(path, heading)`, `(text, heading_substr)`, `(start, end)` — and 14 define `def _sentences(`; ADR 0016's own triage cited "a copy-pasted slicer" as part of a DELETE reason. (3) 30 modules import shared helpers from arbitrary sibling **test** modules — 11 from `tests.unit.test_assurance_filing_rubric`, 5 from `tests.unit.test_review_discipline_context_currency` — a coupling strong enough that the ADR 0016 triage had to annotate a module "Must keep exporting `_sentences`" purely because siblings import from it. A test module that is also a library cannot be deleted, renamed, or converted without auditing its importers, which is exactly the tax the triage paid.

**Where:** e.g. `tests/unit/test_assess_architecture_scope.py:48` vs `tests/unit/test_build_command_consolidated.py:42` (the two root idioms); the 20 `_section` definitions at `tests/unit/test_assess_architecture_scope.py:72`, `tests/unit/test_architecture_watchlist.py:103`, `tests/unit/test_design_system_composition.py:44`, `tests/unit/test_linear_skill.py:115`, `tests/unit/test_update_guidance_same_version_drift.py:86`, and 15 more; the import graph via `grep -rn "from tests.unit.test_" tests/unit/`.

**Why:** `engineering-principles` — duplicated knowledge past any premature-abstraction defence (the shared pattern already exists: `tests/_gitutil.py` is precisely this move, made for git helpers); `code-quality` structure — a helper's home should not be a peer that happens to have defined it first.

**How:** Mechanical, wide, low-risk: add a `tests/unit/_prose.py` (sibling to `tests/_gitutil.py`) exporting `REPO_ROOT` (resolved form) and the genuinely shared slicers; move the helpers that already have external importers (`test_assurance_filing_rubric`'s filing helpers, `_sentences`) into it and re-point the 30 importers; leave deliberately-divergent local slicers alone where their semantics differ. CODE-INSIGHT-3 prevents regrowth.

(`2026-08-04-code.md` has the same content problem but a path out — this report supersedes it and its findings #328/#332/#335–#341 were all verified closed, so step 4's retention folds it normally. `2026-08-04-architecture.md` remains legitimately kept until the next architecture pass. `2026-07-19-pre-publication-readiness.md` self-exempts from the rotation in its own header and was left alone.)

**Where:** `assessments/2026-08-04-system.md`; the rule at `templates/assessment.md:8`; `assessments/LOG.md:14–20` already handles retired *vocabulary* for folded entries but the fold trigger itself has no retired-scope clause.

## Systemic insights

### CODE-INSIGHT-1 — A present-tense quantity in an as-built record must be anchored, derived, or pinned

**Class prevented:** false measured claims accumulating in as-built records — three consecutive instances in `specs/features/guidance-system.md` alone (CODE-1 this pass; one each found by the #445 and #447 reviews). **Exact edit:** extend the existing as-built rule at `skills/spec-authoring/SKILL.md:105` (which today covers enumerated *sets*) with one sentence covering scalar measurements: a present-tense quantity in an as-built record either names the commit it was measured at, is derived by a guard that fails when the two disagree, or is restated as the invariant the number was evidence for — an unanchored count falsifies silently at the next commit that touches its subject. **Generalises:** CODE-1.

### CODE-INSIGHT-2 — The token drift check sweeps consumers for byte-duplicates of token values

**Class prevented:** token knowledge duplicated outside the certified block drifting silently when a token changes (CODE-2 — a class first measured 2026-08-04, unchanged byte-for-byte since). **Exact edit:** extend `scripts/build_design_tokens.py --check` (the gate stage at `scripts/verify.sh:63`) to also scan `docs/index.html` *outside* the generated block for hex literals equal to any resolved token value, failing with the literal, its line, and the `var(--…)` that should replace it — a zero-membership sweep in ADR 0016's sense, since after CODE-2's fix the legitimate count is zero. Add the case to `tests/unit/test_build_design_tokens.py` with a planted-duplicate control. **Generalises:** CODE-2.

### CODE-INSIGHT-3 — A test helper imported by a second module moves to a shared underscore module

**Class prevented:** test modules becoming de-facto libraries whose deletion or conversion requires an importer audit, and helper copies accumulating in divergent spellings (CODE-3 — 132 root constants, 20 slicers, 30 cross-test imports; the ADR 0016 triage already paid this tax in its "Must keep exporting `_sentences`" annotation). **Exact edit:** add one bullet to `CONTRIBUTING.md`'s testing section (beside the mutation-instrument pointer): shared test infrastructure lives in underscore modules (`tests/_gitutil.py`, `tests/unit/_prose.py`) — the moment a second test module needs a helper, the helper moves there; a `test_*.py` module is never an import target. **Generalises:** CODE-3.
