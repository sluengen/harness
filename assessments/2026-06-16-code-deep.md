## Findings

### CODE-1 — SPEC §4.1's registered-command enumeration omits `reclaim` and `checkpoint` — Low

- **What.** `SPEC.md` §4.1 enumerates the CLI's registered surface as "the three audited verbs (`start` / `review` / `close`) plus the read/inspection and ops commands (`status` / `logs` / `events` / `runs` / `worktrees` / `cancel` / `doctor` / `version`)." That list includes the mutating ops verb `cancel` but omits its two registered siblings added since: `reclaim` (CAL-735) and `checkpoint` (CAL-738) — the latter a *lifecycle* verb the orchestrating run calls between `start` and `close`.
- **Where.** `SPEC.md:210-212` (the §4.1 enumeration). The registered set is `harness/cli/__init__.py:66` (`cancel`), `:69` (`reclaim`), `:83` (`checkpoint`).
- **Why.** SPEC's header declares §4 "Current for §4 (core module design)", so §4.1's surface claim is a currency claim. It is now factually incomplete: a reader consulting §4.1 to learn the verb surface misses `checkpoint` (a lifecycle verb) and `reclaim` entirely. The drift is invisible to the gate because `test_cli_surface_locked.py` locks SPEC **§11**'s "Command surface" block against the registered set (`test_cli_surface_locked.py:161-207`) but does **not** guard §4.1's parallel prose list — so §4.1 silently went stale while §11 stayed correct. This is the same dangling-currency-claim class the repo already treats structurally (`test_engine_retired.py`, `test_retired_spec_cites.py`).
- **How.** Make §4.1 stop maintaining a divergent partial list: name the *categories* (audited verbs; read/inspection; mutating ops/maintenance — including the `checkpoint` lifecycle verb and the `reclaim` recovery verb) and defer the *exact registered set* to §11, which is already the single guarded source of truth. Add a focused regression guard so §4.1 can never again present an ops-command enumeration that omits a registered verb. (This fix applies CODE-INSIGHT-1.)

## Systemic insights

### CODE-INSIGHT-1 — Don't keep a second, unguarded copy of the command surface

The surface is enumerated authoritatively in SPEC §11 and locked by `test_cli_surface_locked.py`. §4.1 keeps a *second* hand-list of the same set that nothing guards — so it drifted (CODE-1) while §11 stayed correct. The class: any prose that re-lists a guarded set will eventually diverge from it. The exact edit: rewrite §4.1 to defer the registered list to §11 (no parallel enumeration to drift), and extend `test_cli_surface_locked.py` to assert §4.1 names *no proper subset* of the registered ops commands — i.e. it either lists all of them or defers to §11. Evidence: CODE-1. This generalises the existing "documented surface == registered" guard from §11 to "no doc re-enumerates the surface unguarded."
