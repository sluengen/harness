## Findings

### CODE-1 — The registered-CLI-surface derivation is now duplicated in four test modules — Medium

**What:** The exact two-line pattern that reads Typer's registered command surface —
```python
names = {c.name for c in app.registered_commands if c.name is not None}
names |= {g.name for g in app.registered_groups if g.name is not None}
```
appears byte-identical in four places. Three predate this pass: `tests/unit/test_cli_surface_locked.py:99-100` (`_registered_surface`), `tests/unit/test_feature_specs.py:143-144` (docstring: "Every top-level command and sub-app the Typer app registers"). #219's fix for CODE-3 added the fourth, inline in `tests/unit/test_cli_module_boundaries.py:233-234` (`test_derivation_covers_every_registered_command`), rather than reusing either existing reader.

**Where:** `tests/unit/test_cli_surface_locked.py:99-100`, `tests/unit/test_feature_specs.py:143-144`, `tests/unit/test_cli_module_boundaries.py:233-234`. (`tests/unit/test_hermes_retired.py:94` uses the `registered_commands`-only half of the pattern — a partial, not counted toward the three.)

**Why:** `code-quality` Part B — "Extract on the third strike... If a load-bearing pattern... appears three times, extract it. Twice is a coincidence; three times is duplication." This was already at three occurrences before this pass (the two pre-existing ones), so the fourth landing inline rather than as a shared import is the missed strike. It is also the identical shape of drift the pass's own CODE-3/CODE-INSIGHT-1 fix just taught the guard suite to avoid for *subject sets* — the fix itself introduced sibling duplication in the *reader logic* that computes one. Three modules independently re-deriving "how to read the Typer app's registered surface" means a future Typer API change (or a bug in the derivation, such as forgetting the `registered_groups` half) has to be caught and fixed in three-then-four places rather than one.

**How:** Add `registered_command_surface(app: typer.Typer) -> set[str]` to a small shared test helper module, following the established convention of `tests/_gitutil.py` / `tests/_ledger.py` (e.g. a new `tests/_cliutil.py`, or fold into `tests/_gitutil.py` if a fourth shared file feels like overkill for two lines). Update all four call sites — `test_cli_surface_locked.py`, `test_feature_specs.py`, `test_cli_module_boundaries.py`, and the partial in `test_hermes_retired.py` — to import it.
