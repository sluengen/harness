**Why:** `guidance-coherence`'s universal/repo-specific boundary says universal guidance must not carry repo proper nouns, ticket numbers, or hardcoded repo facts; the hook encodes the same rule for universal prose. `commands/harness.md` is now registered in `registry.yaml` and distributed to consumers, so its ticket IDs pollute installed guidance and produce a warning whenever the file is edited upstream.

**How:** Remove CAL IDs from distributed command prose or replace them with neutral decision/proposal labels already meaningful to consumers. If source-only provenance is still needed, move it to tests, assessments, changelog, or a non-distributed source note. Add a regression guard that runs the same ticket-ID scan over current registered prose files, not only on edited files.
