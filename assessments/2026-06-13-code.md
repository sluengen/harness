## Findings

### CODE-1 — live module docstrings cite a retired SPEC section instead of their as-built §4.x home — Medium

- **What:** `harness/worktree.py:1` and `harness/identity.py:1` each opened their module docstring with `see SPEC §9` / `see SPEC §8`. Both sections are in the **superseded** range: the SPEC.md header ([SPEC.md:4](SPEC.md)) declares the spec "Current for §1–2 … §4 … and §11," and the §3 banner ([SPEC.md:102](SPEC.md)) marks "§3 and §5–§10, §12–§14 … the retired deterministic workflow engine … superseded." Each module has a verbatim as-built home in §4: §4.5 `harness.worktree` ([SPEC.md:238](SPEC.md)) and §4.8 `harness.linear`, `harness.identity` ([SPEC.md:262](SPEC.md)).
- **Where:**
  - `harness/worktree.py:1` — `see SPEC §9` → §9 "Worktree Isolation" (retired node-type framing). Correct: §4.5.
  - `harness/identity.py:1` — `see SPEC §8` → §8 "Run ID and Identity" (retired "generated at workflow start"). Correct: §4.8.
- **Why:** As-built spec divergence (area 9). A reader following the cross-reference lands in retired deterministic-engine prose instead of the current module design. Same defect class as the already-shipped CAL-629 (`_time.py` → retired §12) — but here the correct targets are unambiguous (the §4.x subsection titles are verbatim the module names). The stale cites have been present since the engine retirement (CAL-574) and were never corrected when the sections were superseded.
- **How (actioned, branch `assess/code-2026-06-13`):**
  - `worktree.py:1` → `see SPEC §4.5`; `identity.py:1` → `see SPEC §4.8`.
  - Test-first guard added to `tests/unit/test_engine_retired.py`: `test_module_docstring_cites_asbuilt_section` (parametrized over the two modules) — asserts each docstring cites its `SPEC §4.x` home and does **not** cite the retired `§8`/`§9`. Red before the fix (missing the §4.x cite), green after. Lives alongside the existing retired-engine hygiene guards.
  - CAL-632 filed and moved to In Progress; fixed in this change.
