## Findings

### CODE-1 — `launcher.py` exceeds the 500-line hard limit with no `# size:` justification — Low — **ACTIONED (shipped `0a0aaec`)**

**What:** `harness/launcher.py` is 525 lines (was 446 at the 2026-06-13 assessment — it grew past the limit during CAL-675). `code-quality` Part C requires a file over the 500-line hard limit to carry a one-line `# size: <reason>` justification or reference a tracking ticket; the reviewer rejects an over-limit file with neither. It had neither.

**Where:** `harness/launcher.py:1` — no `# size:` token anywhere in the file.

**Why:** `tests/unit/test_code_quality_size_justification.py` only asserts the *skill text* states the rule; nothing scans the source, so the file slipped through. This is exactly the silent drift CAL-666 introduced the rule to prevent.

**How (done):** Added the `# size:` justification (single cohesive concern: the narrow host launch boundary keeps its allowlist check, `docker run` argv construction, and the `ControlServer` co-located). Subsumed by CODE-INSIGHT-1 below, which makes the rule a suite gate.

### CODE-2 — `test_cli_query.py` docstring names a retired command (`harness validate`) — Low — **OPEN (follow-up)**

**What:** Lines 9 and 13 of `tests/unit/test_cli_query.py` list `harness validate <workflow.yaml>` and describe the file as covering "the `validate` static check." `validate` was retired with the deterministic workflow engine (CAL-574) and is locked *out* of the registered surface by `test_cli_surface_locked.py::RETIRED_COMMANDS`. No `test_validate_*` function exists; the stale text is purely docstring.

**Where:** `tests/unit/test_cli_query.py:9` and `:13`.

**Why:** `test_cli_surface_locked.py`'s live-doc scan checks `.md` and shell sources but skips `.py` files, so this stale reference is invisible to the guard designed to catch exactly this. A developer reading the suite sees a command that does not exist.

**How:** Remove lines 9 and 13. Best done together with CODE-INSIGHT-2.
